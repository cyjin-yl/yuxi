输入框平时很好看，选中文字以后却可能露出另一套颜色。

9 月 27 日的 Proto-UI 提交保存了 Shadcn Input 的选择态证据：浏览器实际选中输入框里的文字，记录明暗主题表现，并在多个 Web 适配器中检查计算样式。这篇按公开记录补写。

## 少见状态不是不存在的状态

组件截图常停在空闲状态：没有焦点、没有选择、没有错误。可读者真正使用输入框时，会选中文本、复制、替换，也会在不同主题间切换。选择态如果没有合适的前景与背景关系，原本清楚的文字就可能变得难以辨认。

这不是给外层容器加一个背景色就能代表的效果。原生输入元素如何绘制选区，需要在真实控件里观察。用普通文本做一块蓝色高亮，测试到的是仿造外观，不是用户实际选中文字时的行为。

公开证据因此记录了具体候选提交、浏览器环境、主题与选择动作。它让截图不再是一张失去上下文的图片，而是某个版本中一段可复现交互的结果。

## 计算样式和截图互相补充

计算样式可以检查颜色是否按规则解析，截图帮助确认最终呈现。二者各有盲区：属性值正确，未必说明读者看到的层叠效果正确；截图看起来正常，也不能证明所有适配器都使用同样的状态传播。

因此记录把真实截图范围与跨适配器探针范围分开。它只声称验证了指定 Input 的 Web 表现，不顺手扩展成非 Web 宿主支持，也不把局部对照写成与整个上游完全一致。

比较引用同样固定到具体上游版本。样式名称可以作为视觉参考，但实现来源、复制范围和验证范围需要各自说明，不能因为长得相近就含糊带过。

我越来越在意这些不在首页大图里的状态。它们通常只出现几秒，却正好出现在读者要做事的时候。页面是否愿意认真照顾这几秒，往往比空闲时多一层阴影更能说明质量。
